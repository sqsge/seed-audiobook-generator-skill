# Chapter 28 Full-Chapter Audio Drama Plan

## Goal

This plan defines how to turn one complete English fantasy chapter into a single continuous audio-drama file using the current Seed 2.0 Pro rewrite plus Seed Audio 1.0 generation workflow.

The target is not a read-aloud audiobook. The target is an English audio drama: the chapter should preserve the complete story arc, key dialogue, character intent, and emotional turns while allowing narration, music, ambience, and foreground SFX to carry compressed action.

## Current Baseline

The latest validated single-section test uses `Chapter 28: Flight of the Prince`, part 5.

The useful baseline result is:

- Audio-drama QA: pass
- ASR language gate: pass
- ASR CJK count: 0
- Output language: English
- Must-keep dialogue coverage: pass
- Beat coverage: pass

This means the single-section mechanism is now acceptable enough to scale cautiously. It does not mean the whole chapter can be generated by simply looping over all parts. The chapter needs chapter-level continuity design first.

## Required Chapter-Level Design

### 1. Chapter Adaptation Plan

Before generating any audio chunks, create one chapter-level adaptation plan.

It should include:

- `chapter_story_arc`: a compact description of the complete chapter progression
- `chapter_source_beats`: all required chapter beats in source order
- `chapter_must_keep_dialogue`: dialogue lines that must appear somewhere in the final audio
- `chapter_optional_dialogue`: dialogue lines that can be compressed or represented through action
- `chapter_narration_strategy`: how the narrator connects compressed action without reading every sentence
- `chapter_omission_policy`: what can be compressed, and what cannot
- `target_duration_range_sec`: expected full-chapter audio-drama duration range

The chapter plan is the control layer. Individual chunk rewrites must not independently decide the whole arc.

### 2. Unified Voice Registry

The full chapter must use one fixed voice registry.

Likely required roles:

- `Narrator`
- `Harry Potter`
- `Severus Snape`
- `Hagrid`
- `Death Eater`
- Optional offstage/background voices only when required

Rules:

- Speaker IDs or generated reference audio must be fixed before chunk generation.
- Every chunk must reuse the same voice registry.
- A role may be absent from a chunk, but if it appears later it must keep the same speaker or reference.
- No chunk may let Seed 2.0 choose a new voice identity for an existing character.

This is the main safeguard against cross-chunk voice drift.

### 3. Music Continuity

The chapter needs one music arc, not separate music per chunk.

Recommended arc:

- Opening: low night tension, distant fire, restrained strings
- Pursuit/combat: pulse grows, sharper staccato accents on spell impacts
- Snape confrontation: score narrows, low sustained pressure under dialogue
- Half-Blood Prince reveal: controlled climax, unresolved final chord
- Aftermath: only if the selected chapter section continues, music recedes into grief/dread

Chunk prompts should use continuity language:

- `continue the same low cello drone`
- `carry the unresolved chord from the previous chunk`
- `duck under dialogue`
- `swell on spell impact`
- `do not cadence here`
- `resolve only at the chapter ending`

Avoid writing a fresh independent score in every chunk.

### 4. Ambience and Space Continuity

The chapter should feel like one continuous place and night.

Reusable ambience palette:

- cold night wind
- burning cabin crackle
- dark grass and footsteps
- distant shouts
- wand crack and spell deflection
- dog howl where relevant
- later crowd/tower/aftermath ambience if the chapter reaches that section

Each chunk should declare:

- `previous_ambience_state`
- `current_ambience_state`
- `next_ambience_state`

This prevents each generated chunk from re-establishing the scene from scratch.

### 5. Chunking Strategy

Do not treat the existing 9 source parts as final audio chunks by default.

Better strategy:

- Start from chapter-level beats.
- Group beats into coherent audio scenes.
- Keep each Seed Audio request under the model's practical length limit.
- Split dense dialogue scenes more finely.
- Allow quieter aftermath scenes to be longer.
- Keep active voices at 3 or fewer per request.

For the current chapter, expected grouping is likely:

| Chapter Section | Function | Chunking Direction |
| --- | --- | --- |
| Opening shock and escape | establishes immediate aftermath and pursuit | medium chunks |
| Corridor/battle movement | action and confusion | shorter chunks |
| Harry vs Snape confrontation | key dramatic core | shorter, dialogue-safe chunks |
| Half-Blood Prince reveal | must preserve key dialogue | isolated climax chunk |
| Hagrid/aftermath | grief and realization | medium chunks |

### 6. Audio Prompt Requirements

Keep the official best-practice natural-language prompt form.

Do not switch to a rigid bracketed script format.

Every final Audio prompt should include:

- voice continuity mapping with `actor is <<TGT_SPKn>>`
- English speech lock: `All audible speech must be English only. Do not translate or speak Chinese.`
- continuous ambience
- continuous music arc reference
- foreground action SFX
- actual quoted character lines for must-keep dialogue
- explicit Narrator lines only when narration should be spoken
- non-spoken production directions clearly framed as sound-design events

Important rule:

Non-quoted ambience, music, action, and sound-design descriptions are production directions only. Spoken narration must be explicit and bound to `Narrator`.

### 7. ASR Gate

Every generated chunk must pass ASR before it can enter the chapter stitch.

For English mode:

- ASR language hint: `en-US`
- `cjk_char_count` must be 0
- ASR transcript must contain enough English words
- must-keep dialogue should be approximately recoverable in ASR
- if ASR detects Chinese/CJK output, regenerate the chunk

This is now mandatory because prompt-level English checks are not sufficient. A pure-English prompt can still produce mixed-language audio.

### 8. Stitching and Post-Processing

The final chapter audio should be built only after all chunks pass:

- generation validation
- audio decode validation
- silence/tail checks
- audio-drama QA
- ASR language gate

Stitching rules:

- trim long tail silence per chunk
- keep short natural breath gaps
- avoid hard music resets
- normalize loudness across chunks
- check for repeated lines at boundaries
- check for missing story beats at boundaries
- export one full-chapter wav

### 9. Chapter-Level QA

The chapter-level report should include:

- full chapter duration
- chunk count
- all chunk durations
- ASR status per chunk
- final full-chapter ASR status
- source beat coverage
- must-keep dialogue coverage
- omitted/compressed content rationale
- voice registry used
- music arc summary
- ambience continuity summary
- silence and tail-silence report
- known residual risks

The most important acceptance criteria are:

- The final audio is English.
- All must-keep dialogue is present or intentionally represented.
- The chapter story arc is understandable without reading the source.
- Music and ambience feel continuous.
- Main character voices remain stable.
- No chunk with ASR-detected Chinese enters the final stitch.

## Implementation Sequence

Recommended implementation order:

1. Add a chapter-level planner that creates `chapter_plan.json`.
2. Add unified voice registry generation and reuse.
3. Add chapter-level music and ambience arc files.
4. Add a batch runner that generates each chunk into `outputs/chapter_runs/.../chunks/chunk_XXX/`.
5. Run Seed Audio per chunk.
6. Run ASR immediately per chunk.
7. Regenerate failed chunks.
8. Stitch only passing chunks.
9. Run final chapter ASR and QA.
10. Produce the chapter-level report.

Do not run all 9 parts blindly until steps 1-4 are implemented.

## Implemented Workflow Entry

The chapter-level workflow entry is:

```bash
python3 scripts/chapter_audio_workflow.py \
  --source-file outputs/manual_inputs/20260706_magic_novel_chapter28/chapter28_flight_of_the_prince_source.txt \
  --case-id chapter28_flight_of_the_prince_e2e \
  --attempt-id <attempt_id> \
  --generate
```

The entry does not replace the existing single-section generation engine. Instead, it wraps it:

1. Clean the complete chapter source.
2. Split the chapter into audio-sized story sections.
3. Write a fixed chapter-level voice registry.
4. Write one story config per section with `lock_roles=true`.
5. Run API preflight for Seed2, TTS references, Seed Audio generation, and ASR.
6. Run the public `scripts/audio_drama_skill.py` entry point for the approved run.
7. Require every section to pass its local audio QA and ASR language gate.
8. Stitch the full chapter only after all sections pass.
9. Write `chunk_manifest.json`, `reports/chapter_quality_report.json`, and `reports/chapter_asr_report.json`.

For a dry directory/config check without model calls:

```bash
python3 scripts/chapter_audio_workflow.py \
  --source-file outputs/manual_inputs/20260706_magic_novel_chapter28/chapter28_flight_of_the_prince_source.txt \
  --case-id chapter28_flight_of_the_prince_e2e \
  --attempt-id prepare_only_full \
  --prepare-only
```

The current default split for this chapter produces 8 audio-sized sections with `target_chars=2400` and `max_chars=2800`.

The chapter split must pass source coverage before generation. `reports/chapter_quality_report.json` exposes:

- `acceptance.source_coverage_ok`
- `acceptance.source_coverage`
- `acceptance.section_char_summary`
- `acceptance.speaker_reuse_warnings`
- `acceptance.all_sections_quality_pass`
- `acceptance.all_sections_asr_pass`

Required generation environment:

- Seed2 rewrite: `LLM_API_KEY`, `ARK_API_KEY`, `BYTEPLUS_API_KEY`, or `OPENAI_API_KEY`
- TTS voice references: `TTS_API_KEY` only when roles use `reference_mode=tts_audio`
- Seed Audio generation: `SEED_AUDIO_API_KEY`, `TTS_API_KEY`, `BYTEPLUS_API_KEY`, or legacy `SEED_AUDIO_APP_ID` plus `SEED_AUDIO_ACCESS_KEY`
- ASR language gate: `LAS_API_KEY` or `ASR_API_KEY`

For the Chapter 28 case, roles use fixed BytePlus `speaker` references by default, so the workflow does not need to synthesize dry TTS reference clips before Seed Audio generation.

The workflow writes `preflight.json` before generation. If the environment is incomplete, the attempt fails before any section generation starts and updates `latest_attempt.json`.

## Tuning Loop

If an attempt fails or the generated audio quality is poor, tune at the section level first:

- Inspect `attempts/<attempt_id>/reports/chapter_quality_report.json`.
- Find the failing or weak `chunk_XXX`.
- Inspect that section's `logs/audio_quality_report.json`, `logs/asr_language_report.json`, and `05_director_prompt_chunks/*.txt`.
- Tune the workflow rule that caused the weakness, not the one-off prompt text.
- Re-run the chapter with a new `attempt_id`.

The chapter stitch is deliberately gated. A section with failed ASR, weak QA, missing audio, or missing final audio should not enter the final chapter file.

For focused tuning, rerun only the weak section:

```bash
python3 scripts/chapter_audio_workflow.py \
  --source-file outputs/manual_inputs/20260706_magic_novel_chapter28/chapter28_flight_of_the_prince_source.txt \
  --case-id chapter28_flight_of_the_prince_e2e \
  --attempt-id tune_chunk_003_001 \
  --only-section chunk_003 \
  --generate
```

For later continuation from a section:

```bash
python3 scripts/chapter_audio_workflow.py \
  --source-file outputs/manual_inputs/20260706_magic_novel_chapter28/chapter28_flight_of_the_prince_source.txt \
  --case-id chapter28_flight_of_the_prince_e2e \
  --attempt-id continue_from_chunk_004 \
  --start-section chunk_004 \
  --generate
```
